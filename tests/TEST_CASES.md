# 鮮農直送網 訂單系統：測試案例

| 項目 | 內容 |
|---|---|
| 受測系統 | 舊系統 `legacy_demo/`（CodeIgniter 1.7.2，PHP4 語法，執行環境 PHP 5.6 + MariaDB） |
| 測試方式 | 黑箱測試，只透過 HTTP 呼叫 API 和後台，不依賴程式內部 |
| 自動化 | `tests/characterization/`（pytest），每個案例都標有對應的測試函式 |
| 用途 | 1. 記錄舊系統**現在實際的行為**（包含 Bug）<br>2. 改寫後拿同一份案例驗收新系統 |

## 閱讀說明

**案例類型**
- **規則**：現有商業規則，新系統必須完全一樣
- **Bug**：已知錯誤，新系統必須修正，案例會同時寫出「舊行為」和「新系統預期」
- **資安**：資安弱點，新系統不能再出現
- **待決策**：行為可疑，需要業務決定新系統要不要保留。舊系統照現況驗證，新系統暫時略過
- **舊系統限定**：後台頁面這類功能，新系統不一定提供

## 2. 已知 Bug

| 編號 | 問題 | 舊行為 | 新系統預期 |
|---|---|---|---|
| BUG-01 | 取消訂單沒有把庫存加回去 | 庫存不變 | 加回 |
| BUG-02 | 扣庫存沒有交易保護，而且是讀出、計算、再寫回 | 同時下單會超賣 | 不超賣，庫存不會變負數 |
| BUG-03 | 訂單編號是亂數，沒有唯一索引 | 可能重複 | 唯一 |
| BUG-04 | 同一商品重複出現在同一筆訂單 | 各自比對庫存並互相覆寫，少扣庫存 | 合併計算 |
| BUG-05 | 收件人含單引號 | SQL 錯誤，錯誤頁還會印出 SQL | 正常建單 |
| BUG-06 | 付款通知 chk 空白就跳過驗證 | 可以偽造付款 | 拒絕 |
| BUG-08 | 取消 API 的 member_id 可以做 SQL Injection | 可以取消別人的訂單 | 拒絕 |
| BUG-09 | 電話訂購從 API 複製建單流程時，**漏掉試吃包限購** | 可以訂 3 包 | 和 API 一致 |
| BUG-10 | 購物車的 VIP 省下金額和實際折扣算法不同（四捨五入或捨去，逐項或整筆） | 1001 元的商品顯示省 150，實際折 151 | 顯示金額和實際一致 |
| BUG-11 | 購物車免運提示沒有判斷離島 | 金門會員看到「符合免運」，結帳被收 250 | 提示正確 |
| BUG-12 | 後台修改收件郵遞區號時不重算運費 | 改成澎湖仍然收 0 元運費 | 重算或禁止修改 |
| BUG-13 | 後台刪除訂單直接 DELETE | 庫存不加回、沒有任何紀錄 | 改成作廢並加回庫存 |
| BUG-14 | 電話訂購畫面的 JS 試算淨值用 `Math.round`，伺服器用 `intval` | 畫面顯示的淨值可能比實際多 1 元 | 統一由伺服器計算 |

> BUG-03 沒辦法用黑箱方式穩定重現；BUG-14 是瀏覽器端的 JavaScript，HTTP 測試測不到。這兩項只列在清單裡，沒有自動化測試。BUG-09～13 都屬於舊系統限定的功能（前台、後台），新系統若要改寫這些功能，必須一併修正。BUG-07 原本是金額寬鬆比較，驗證後發現比較像規格問題，已改列為 DEC-03。
